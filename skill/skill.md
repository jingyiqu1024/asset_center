# 知识内容智能管理 (Document Context Management) v1.0

## 概述

本 skill 帮助用户通过 Agent 直接管理资源管理平台中的知识文档内容，无需手动登录平台即可完成对知识文档的更新、修改。

### 核心功能

- **身份认证**: 通过用户身份登录资源管理平台，确保操作权限
- **内容提取**: 从上传文档、对话记录或直接输入中提取核心内容
- **格式匹配**: 自动检测文档格式并进行相应转换
- **Diff 对比**: 替换模式下展示清晰的变更对比
- **操作审计**: 记录所有操作的操作人和时间戳

## 完整工作流程

### 步骤 1: 用户身份认证

**目标**: 确保用户有权限访问和修改目标文档

**实现脚本**: `skill/scripts/01_auth.js`

**流程说明**:
1. 检查当前是否已有有效 session
2. 若已登录，直接使用现有认证信息继续
3. 若未登录，引导用户完成 SSO 登录
4. 登录成功后，验证用户对目标文档的编辑权限

**用户交互**:
- 已登录：自动跳过，提示"✅ 用户已登录: {用户名}"
- 未登录：提供登录链接，等待用户完成认证

---

### 步骤 2: 提取和总结核心内容

**目标**: 从不同来源提取内容并生成描述性总结

**实现脚本**: `skill/scripts/02_summarize.js`

该脚本包含三个场景：

#### 场景 A: 上传文档总结
- 支持 PDF、Word 格式
- 自动提取文档结构、段落、列表
- 生成标题、概述、核心要点

#### 场景 B: 对话记录总结
- 读取当前会话的历史消息
- 识别讨论要点、关键决策、参与者
- 生成结构化的会议/讨论总结

#### 场景C: 直接文本输入
- 接收用户直接输入的文字内容
- 自动判断内容类型（结构化/段落/列表）
- 优化格式后输出

**用户交互**:
- 告知用户正在分析的内容来源
- 完成后展示总结预览，进入步骤3

---

### 步骤 3: 用户确认内容

**目标**: 让用户确认总结内容是否正确，是否需要修改

**实现脚本**: `skill/scripts/03_confirm.js`

**流程说明**:
1. 展示总结内容（标题、概述、核心要点、关键决策）
2. 询问用户是否确认

**用户交互** (三选一):
- **确认内容** → 进入步骤4
- **修改内容** → 进入逐项编辑流程，完成后继续
- **重新生成** → 返回步骤2重新分析

---

### 步骤 4: 选择更新位置和模式

**目标**: 确定内容要更新到文档的哪里，以及用什么方式

**实现脚本**: `skill/scripts/04_select_target.js`

**流程说明**:
1. 询问用户选择更新模式
2. 若为插入或替换模式，列出文档章节供用户选择

**用户交互** (三选一):
- **追加到末尾** → 直接进入步骤5
- **插入到指定章节后** → 列出章节，选择后进入步骤5
- **替换现有内容** → 列出章节，选择后进入步骤5，并在步骤6生成Diff

---

### 步骤 5: 格式匹配和内容转换

**目标**: 检测原始文档格式，将更新内容转换为匹配的格式

**实现脚本**: `skill/scripts/05_format_match.js`

**流程说明**:
1. 检测文档格式（HTML / Markdown / 纯文本）
2. 分析周边内容的格式特征（标题级别、列表风格等）
3. 将总结内容转换为匹配的格式

**支持的输出格式**:
- **HTML**: 带 `<h2>`/`<h3>`/`<ul>`/`<p>` 标签的结构化 HTML
- **Markdown**: 带 `##`/`-`/`**` 的标准 Markdown
- **纯文本**: 带分隔线的纯文字格式

---

### 步骤 6: 生成 Diff（替换模式专用）

**目标**: 当用户选择替换模式时，生成详细的 diff 对比

**实现脚本**: `skill/scripts/06_diff.js`

> ⚠️ 仅在步骤4选择"替换现有内容"时执行，追加/插入模式跳过此步骤。

**流程说明**:
1. 获取被替换章节的原始内容
2. 与新内容逐行对比，标注新增/删除/修改
3. 展示变更统计（+新增行数、-删除行数、~修改行数）
4. 展示详细变更预览（前20行）

---

### 步骤 7: 最终确认

**目标**: 向用户展示最终的变更内容和格式，获得确认后保存

**实现脚本**: `skill/scripts/07_final_confirm.js`

**流程说明**:
1. 汇总展示：目标文档、操作模式、目标位置、操作人（将被记录）
2. 展示格式化后的内容预览（前500字）
3. 若有 Diff，展示变更统计

**用户交互** (二选一):
- **确认保存** → 进入步骤8执行保存
- **取消操作** → 终止整个流程

---

### 步骤 8: 保存更新

**目标**: 执行文档更新并记录修改信息

**实现脚本**: `skill/scripts/08_save.js`

**流程说明**:
1. 构建包含操作人信息的更新请求
2. 调用 `/api/documents/{id}/update` 接口
3. 失败时自动重试（最多3次，指数退避）
4. 成功后记录到 `.agent-history/document-updates.json`

**输出**:
- 文档链接
- 新版本号
- 修改人和时间戳

---

### 步骤 9: 可选召回测试

**目标**: 根据用户意愿决定是否进行召回测试

**实现脚本**: `skill/scripts/09_recall_test.js`

**流程说明**:
1. 询问用户是否需要召回测试（默认跳过）
2. 若选择测试：等待索引更新（3秒）→ 提取关键词 → 搜索验证 → 计算召回率
3. 展示召回测试报告和互动问答测试结果

**用户交互** (二选一):
- **跳过测试** *(默认推荐)* → 流程结束
- **需要测试** → 执行召回验证，输出召回率报告

## 错误处理

| 错误类型 | 原因 | 处理方式 |
|---------|------|---------|
| 认证失败 | 登录超时或 Token 过期 | 重新引导登录，检查账号权限 |
| 权限不足 | 无文档编辑权限 | 提示联系文档所有者授权 |
| 保存失败 | 网络或服务端错误 | 自动重试3次（指数退避），失败后报错 |

详细错误处理逻辑见各步骤对应脚本。

## 安全性和审计

- **操作审计**: 所有文档操作记录操作人（userId、displayName）和时间戳
- **版本控制**: 每次更新自动创建新版本（v1 → v2 → v3）
- **备份机制**: 更新前自动创建备份，支持通过备份ID恢复

详见 `skill/config.js` 的 `security` 配置项。

---

## 最佳实践

1. **身份验证优先**: 任何操作前先确保用户已认证
2. **权限检查**: 每次写操作前检查用户权限
3. **内容确认**: 多轮确认机制，避免误操作
4. **格式匹配**: 严格匹配原文档格式，保持一致性
5. **Diff 可视化**: 替换操作必须展示清晰的 diff
6. **审计追踪**: 记录所有操作，包括操作人和时间戳
7. **备份机制**: 更新前自动备份，防止数据丢失

---

## 注意事项

⚠️ **重要提示**:

1. **修改人记录**: 所有更新操作都会记录真实的操作人信息，请谨慎操作
2. **权限管理**: 确保您有足够的权限访问和修改目标文档
3. **格式一致性**: 系统会自动匹配文档格式，但复杂格式可能需要手动调整
4. **Diff 确认**: 替换模式下请仔细检查 diff，避免误删重要内容
5. **召回测试**: 召回测试是可选的，根据实际需求决定是否执行
